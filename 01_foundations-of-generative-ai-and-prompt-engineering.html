SECTION 1

Discriminative AI vs Generative AI

Both types learn from data, but they answer different questions. A discriminative model draws a boundary between categories. A generative model learns the pattern of the data itself, so it can produce new samples that follow that pattern.

Discriminative AIGenerative AI
GoalIdentify or classifyCreate new content
OutputA label, score, or classText, images, code, audio
ExampleSpam / not-spam email filterChatGPT writes the email
Typical modelsLogistic regression, BERT classifiers, CNN classifiersGPT, Llama, Granite (LLMs), diffusion models
Remember: Discriminative asks “Which category does this belong to?” Generative asks “What new thing can I create?”
In practice: Real systems often combine both. A RAG chatbot can use a discriminative step, such as a classifier or reranker that scores which documents are relevant. A generative LLM then writes the final answer.
SECTION 2

Prompts & prompt engineering

A prompt is the input you give an LLM to guide it toward a task. Prompt engineering is the process of designing and refining those questions, commands, or statements until the responses are relevant and accurate.

Anatomy of a prompt: 4 elements

Click a legend item to highlight that part of the prompt.

Instruction: what to do Context: background information Input data: what to process Output indicator: where/how to answer
Classify this customer review as positive, negative, or neutral.
Product: Recently launched
Review: "The product arrived late but the quality was excellent."
Sentiment: ___

Why prompt engineering matters

🎯 Accuracy

More correct answers, with fewer hallucinations and misunderstandings.

🧭 Relevance

The answers fit what the user actually wants.

♻️ No constant fine-tuning

The same model adapts to new tasks by changing only the prompt. That is cheaper and faster.

Bad vs good prompt

Vague
Summarize this.
Engineered
You are a financial analyst.            ← role/context
Summarize the report below in 3 bullet
points for a non-technical manager.     ← instruction
Report: """{report_text}"""             ← input data
Summary (3 bullets):                    ← output indicator
SECTION 3

In-context learning & zero / one / few-shot

In-context learning (ICL) means teaching the model with examples (demonstrations) inside the prompt. The model spots the pattern and applies it to a new input. No retraining or fine-tuning is needed, and the model weights never change.

The “shots” spectrum

Classify this statement as true or false.
Statement: The Eiffel Tower is in Berlin.
Answer:

When: simple, well-known tasks the model already understands. Fastest and cheapest.

Translate English to French.
English: How is the weather today?  →  French: Quel temps fait-il aujourd'hui ?
English: Where is the supermarket?  →  French:

When: you need to show the exact format or style once.

Review: "Loved it, works perfectly!"   → Positive
Review: "Broke after two days."        → Negative
Review: "It's okay, nothing special."  → Neutral
Review: "Arrived late but great quality." →

When: the task is subtle, domain-specific, or needs a consistent output format.

Remember: ICL = learn from examples in the prompt, without retraining. Zero = 0 examples, One = 1, Few = several.
Common pitfall: In few-shot prompts, the model also copies your examples’ biases. If all your examples are “Positive,” it will lean positive. Balance the labels and vary the examples.
SECTION 4

Chain-of-Thought & Self-Consistency

Chain-of-Thought (CoT)

The model solves a complex problem step by step instead of jumping straight to an answer. This works well for math, logic, and multi-step reasoning. You can trigger it with worked examples, or simply add “Let’s think step by step.”

Self-Consistency

Generate several independent reasoning paths for the same question (usually with temperature > 0), then compare them and pick the most common answer (majority vote).

TechniqueCore ideaTrade-off
CoTOne step-by-step reasoning pathLonger outputs; still one chance to be wrong
Self-consistencyMany CoT paths → voteMore reliable, but N× the cost and latency
Remember: CoT = solve step by step. Self-consistency = multiple solutions → compare → reliable answer.
SECTION 5

LangChain & prompt templates

LangChain is a Python (and JS) framework for building LLM applications. The “chain” in the name means connecting several operations, for example: retrieve → extract → process → generate.

LangChain is the glue between an LLM and everything around it.
Modularity

Reusable building blocks you can swap, for example changing the LLM provider without rewriting the app.

Extensibility

Easily add features and connect external systems.

Decomposition

Break complex tasks into small, testable steps.

Vector DB integration

Semantic search finds relevant information. This is the basis of RAG.

Common uses: document summarization · data extraction · Q&A systems · customer support · automated writing · report analysis · technical documentation.

Prompt templates: try it

A prompt template is a reusable prompt with {placeholders}. It is reusable, consistent, easy to change, and works with different inputs.

"Tell me a {adjective} joke about {content}."
from langchain_core.prompts import PromptTemplate

prompt = PromptTemplate.from_template("Tell me a {adjective} joke about {content}.")
prompt.format(adjective="funny", content="chickens")
# → 'Tell me a funny joke about chickens.'
SECTION 6

LCEL: LangChain Expression Language

LCEL connects components with the pipe operator |, like an assembly line. Each step does one job and passes its output to the next step.

from langchain_core.prompts import PromptTemplate
from langchain_core.output_parsers import StrOutputParser
# In the IBM labs: from langchain_ibm import WatsonxLLM  (any chat model works, e.g. ChatOpenAI)

prompt = PromptTemplate.from_template("Tell me a {adjective} joke about {content}.")
chain  = prompt | llm | StrOutputParser()
chain.invoke({"adjective": "funny", "content": "cats"})

Sequential vs parallel execution

from langchain_core.runnables import RunnableParallel, RunnableLambda

summarize = summary_prompt   | llm | StrOutputParser()
translate = translate_prompt | llm | StrOutputParser()
sentiment = sentiment_prompt | llm | StrOutputParser()

# Parallel: same input → dict of results
analysis = RunnableParallel(summary=summarize, translation=translate, sentiment=sentiment)
analysis.invoke({"text": article})

# Type coercion: a plain dict inside a chain becomes a RunnableParallel automatically
chain2 = {"summary": summarize, "sentiment": sentiment} | report_prompt | llm

# RunnableLambda: wrap any Python function as a step (plain functions are coerced too)
word_count = RunnableLambda(lambda s: len(s.split()))
chain3 = summarize | word_count

The Runnable family

RunnableSequence

Runs steps in order. a | b | c is the short syntax.

RunnableParallel

Runs independent tasks concurrently on the same input and returns a dict.

RunnableLambda

Turns a Python function into a chain step.

Every Runnable shares the same interface: .invoke() (one input), .batch() (many inputs), .stream() (token by token), plus async versions such as .ainvoke().

LCEL or LangGraph?

Use LCEL when…Use LangGraph when…
The flow is linear or a simple fan-out: summarize, Q&A, translateYou need branching, loops, retries, memory/state, or decisions made by the agent
Remember: LCEL = prompt templates + connected components + the | operator.
SECTION 7

Agents

An agent is an LLM-powered system that uses prompts and tools to perform complex tasks. A plain chain follows a fixed path. An agent decides which tool to use next based on what it has observed so far.

LLM + Tools + Prompts = an agent that can handle complex tasks (the ReAct-style loop).

❓ Q&A agents

Answer questions using sources such as documents and the web.

✍️ Content agents

Create or summarize content.

📊 Analytics agents

Analyze data, for example by running SQL or pandas.

🌍 Multilingual agents

Translate and localize content.

Remember: Chain = a fixed recipe. Agent = a cook who chooses which tool to use next.

SECTION 11

Interview questions (with model answers)

What is the difference between prompt engineering and fine-tuning? When would you choose each?Prompt engineering changes the input. It is fast, cheap, needs no training data, and leaves the weights untouched. Fine-tuning changes the model weights using labeled data. Start with prompting (zero → few-shot → CoT), then add RAG if the model is missing knowledge. Fine-tune only when you need a consistent style or format at scale, lower latency or cost with a smaller model, or behavior that prompts can’t reliably produce.
Why does few-shot prompting work if the model isn’t retrained?LLMs learned during pretraining to continue patterns. The demonstrations in the context window condition the model’s next-token predictions toward the format and mapping you showed. This is in-context learning, and the weights never change.
What are the downsides of chain-of-thought and self-consistency in production?They produce more tokens, which means higher cost and latency. Self-consistency multiplies that by N samples. The reasoning can also be plausible but wrong, so you should validate outputs. Use them only for tasks that really need reasoning, and cap N.
Explain prompt | llm | parser. What does each part return?The PromptTemplate takes a dict and returns a PromptValue. The LLM or chat model returns a string or an AIMessage. StrOutputParser returns a plain string (JsonOutputParser returns a dict). Each step is a Runnable with invoke, batch, and stream.
When would you use RunnableParallel?Use it when several independent operations need the same input. For example, you might summarize, classify sentiment, and extract entities from one document at the same time. It cuts latency and returns a dict that you can feed into a later step.
Chain vs agent: what’s the difference?A chain runs a fixed, predefined sequence of steps. An agent uses the LLM to decide which tool to call next, and in what order, based on intermediate observations. Agents are more flexible but less predictable, so they need guardrails, step limits, and logging.
How would you make a prompt more reliable for a classification task?Give a clear instruction and a fixed label set. Add balanced few-shot examples and an explicit output format, such as JSON with an enum. Set temperature to 0. Validate the output with a parser, and evaluate on a labeled test set while you iterate.
